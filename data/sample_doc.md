# AI Agent 面试知识点手册（示例语料）

> 本文件是项目的**示例语料**，用于把 RAG 链路跑通。
> 换语料：在 `.env` 里把 `CORPUS_PATH` 改成你自己的文档（技术笔记/产品说明书/课程资料，.md 或 .txt，UTF-8）。

## 一、Agent 基础概念

AI Agent 是一种能够自主完成多步任务的智能体：它接收目标后，自己规划步骤、调用工具获取信息、观察结果并调整策略，直到完成任务或达到上限。与单次 LLM 调用不同，Agent 是"规划→工具调用→观察→更新状态"的闭环决策过程，而单次调用是一次性的开环生成。

Agent 和 Workflow 的区别：Workflow 是预先写死的固定编排，步骤和分支在运行前就确定；Agent 在运行时根据当前状态动态决定下一步。生产系统中两者常结合使用：Workflow 负责稳定的主流程，Agent 负责流程内需要灵活判断的分支。

Function Calling 是模型的一种能力：模型根据工具描述（schema）输出结构化的调用请求，由应用代码真正执行。它是 Agent 调用工具的底层机制，本身不是 Agent。Agent 是决策框架，Function Calling 是执行通道。

MCP（Model Context Protocol）是工具接入的标准化协议，解决了"每个工具都要单独写对接代码"的碎片化问题。有了 MCP，Agent 通过统一协议发现和调用工具，新增工具不需要改 Agent 代码。

ReAct 循环是 Agent 的一种经典实现模式：思考（Thought）→ 行动（Action，调用工具）→ 观察（Observation）→ 再思考，循环直到给出最终答案。用裸 Python 手写 ReAct 能真正理解 Agent 的机制，而不是只会调框架。

## 二、RAG 知识库

RAG（Retrieval Augmented Generation，检索增强生成）是给大模型注入外部知识的常用方案：用户提问后，先从知识库检索相关片段，拼进 Prompt，再让模型基于这些片段回答。它解决模型知识过时、缺乏私域数据、容易幻觉的问题。

RAG 和 Agent 不是对立关系：RAG 是 Agent 工具箱里的"知识查询器"。Agent 判断"这个问题需要外部知识"时，就调用 RAG 检索工具获取片段，再继续推理。RAG 回答知识型问题，Agent 负责统筹整个任务的执行。

RAG 链路一般分四步：文档加载、切片（chunking）、检索（retrieval）、生成（generation）。切片大小（chunk size）和重叠（overlap）直接影响检索效果：chunk 太大，片段语义混杂、命中不精准；chunk 太小，上下文不完整。常见做法是先按段落切，超长段再按字符切，并保留 10% 左右的重叠。

检索有两种主流实现：BM25（基于词频的稀疏检索，无需训练、可解释、零成本）和向量检索（把文本嵌入到向量空间做相似度搜索，能理解语义）。小语料、中文场景下 BM25 配合中文分词（如 jieba）已经够用；语料变大或需要语义匹配时再升级向量检索。

检索不到相关内容时，模型仍然硬答就是幻觉的常见来源。兜底策略：系统提示词里写明"检索不到就明确说不知道"；把检索结果作为引用来源展示；对低分结果做阈值过滤。

## 三、生产环境的坑与兜底

Agent 生产环境高频坑：死循环（一直调工具不收敛）、调用不存在的工具、上下文污染（工具结果垃圾信息混入）、Token 爆炸、Prompt Injection（恶意指令注入）。对应兜底：最大步数限制、工具名校验白名单、上下文截断、输出长度截断、数据与指令分离（把不可信内容标记为数据而非指令）。

Prompt Injection 指用户或外部数据中夹带指令，诱导模型执行非预期操作。防护要点：把系统指令和外部数据明确分层（用标记区分"指令"与"数据"）、对工具调用做白名单校验、敏感操作加人工确认。

评测 Agent 项目不能只看"答得对不对"，常用指标：检索命中率（top-k 里有没有正确答案）、回答准确率（人工或 LLM 打分）、端到端任务成功率、延迟和 Token 成本。面试讲项目时，能说出"用什么指标、怎么测、基线是多少"是加分项。

## 四、调优经验

检索不准时先排查三个变量：chunk size（切片大小）、chunk overlap（重叠）、top_k（返回条数）。调优方法：构造 20 个左右的测试问题，手动标注期望命中的段落，跑检索看命中率，再逐步调参，每次只改一个变量。

中文 RAG 的分词会影响检索：jieba 是常用的中文分词库。切词粒度不当会导致检索偏差，比如领域词被切成无意义词。可以用自定义词典补充领域词汇。

## 五、面试高频概念题

面试官常问"Agent 和单次 LLM 调用的区别"：单次调用是开环生成，一次输入一次输出；Agent 是闭环决策，有状态、会迭代、能调用工具。一句话总结：Agent = 目标 + 规划 + 工具 + 循环 + 停止条件。

面试官常问"Agent 和 Workflow 的区别"：Workflow 是固定剧本，Agent 是即兴演出。Workflow 适合流程稳定的场景，Agent 适合需要动态决策的场景，两者可嵌套使用。

面试官常问"MCP 解决什么问题"：解决工具接入碎片化。标准协议让工具可以即插即用，Agent 不需要为每个工具写适配代码。

面试官常问"RAG 和 Agent 的关系"：RAG 不是 Agent 的对立面，是 Agent 工具箱里的知识查询器。Agent 判断需要知识时调用 RAG，两者组合解决"不知道"和"不会做"两类问题。
